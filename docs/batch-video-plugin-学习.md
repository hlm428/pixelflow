# batch-video-plugin 学习笔记（2026-11-04）

来源：GitHub zysen1/batch-video-plugin（2026-11-01 创建，MIT 开源，32 星、11 fork）。
作者 Jarvis 在 X 上说它“很好地解决了角色一致性的问题”。
注意：这是根据公开工作流描述从零写的独立重构版，不是 Muse 内插件导出的代码；**不自带视频生成模型**，默认 mock 后端只用 ffmpeg 生成占位片段，要出真片子得自己接供应商。

## 工作流（10 步）

1. **项目**：一句话故事、类型、横/竖屏、每镜候选数（1–6）、自动模式。
2. **分镜规划**：把故事拆成 N 个 10 秒镜头，每个镜头有运镜、画面、台词、起始画面、结束画面。默认是模板化规划，规划结果可在页面上改。
3. **风格圣经**：人物锁定 / 场景锁定 / 视觉锁定三段。组装提示词时三段锁定逐字放进每个镜头的完整提示词前面，再加真实感母版（电影感摄影、柔和均匀光线、同一光源同一色温、真实皮肤不磨皮、表情放松不摆拍、真实环境声无配乐、画面内不烧录水印字幕文字、背景不出现可读文字）与接力规则（第 2 镜起从上一镜尾帧接续）。
4. **抽卡派发与自动续跑**：每轮最多 6 条成功视频（失败不计数），超出的排队；本轮最后一条回报到即自动派下一轮；派发失败回排队（最多 3 次，之后标为失败）；30 分钟无动静的僵死轮次由下一轮接管（看门狗每分钟巡查）；成片后不再自动生成多余候选；每镜可抽 1–6 条候选。
5. **选片**：上报每条候选的文件、规格检查注、接缝分与真实感分；自动模式下第一条完成的候选即为选定，后续更高分不自动替换。
6. **终审**：对每条选定片抽首 / 中 / 尾帧，按 15 类假信号检查（塑料皮肤、表情僵、光线色温漂移、服装发型跳变、身份漂移、接缝机位跳变、招牌乱码、道具消失、口型不清等），每镜给 pass / warn / fail 判定、真实感分、接缝分与具体剪辑修法（含裁剪秒数）。**规格检查（时长 / 分辨率 / 音频）与真实感分开计分，规格通过不等于真实感通过；对白逐字核对明确标注为“抽帧无法核口型、未验证”。**
7. **二次剪辑方案**：按终审自动生成可执行精剪方案（每镜裁剪点、接缝处硬切或 2–3 帧叠化、全片统一色温曝光、统一响度、轻颗粒破塑料感）；剪不了的镜头不硬剪，列入再抽清单；方案可人工编辑。
8. **执行与定稿**：按方案用 ffmpeg 真剪出完善版；用户点“定稿”才算完；不通过镜头可一键再抽并重新补审。
9. **发布文案**：自动生成，内含“本片全部画面由 AI 生成，非实拍”的 AI 标识；画面内不烧录任何水印或文字。
10. **播放与导入**：已成候选可播放、成片区整片连播；支持从磁盘导入已有视频作为候选。

## 技术要点

- 环境：Python 3.12+、ffmpeg / ffprobe 在 PATH 中。**零 pip 依赖**，只用 Python 标准库 + SQLite + ffmpeg。
- 启动：`python3 server.py --port 8000`，打开 http://127.0.0.1:8000。数据写到 `./data/`（SQLite + 生成的视频）。
- 架构：server.py（HTTP 服务、看门狗线程、启动恢复）；batch_plugin/db.py（SQLite）；planner.py（模板化分镜规划，可替换为模型规划）；prompts.py（锁定 + 真实感母版 + 接力规则的提示词组装）；adapters.py（视频后端接口 + mock 适配器 + 供应商模板）；engine.py（轮次引擎）；review.py（终审）；editplan.py（精剪方案）；assemble.py（ffmpeg 两段式渲染：裁剪 → 接缝链 → 颗粒）；publish.py（发布文案）；httpapi.py（JSON API 与静态页面）；web/（原生 JS 前端，无构建步骤）。
- 接入真实视频后端：在 `batch_plugin/adapters.py` 中实现 `VideoBackend.generate(prompt, out_path, orientation, duration=10.0, meta=None)`，在 server.py 里把 MockAdapter() 换成自己的适配器。约定：时长 10 秒、方向一致、只写一个完整文件、失败时删掉残缺输出、画面内不烧录水印字幕文字。
- AI 标识规则写死在两处：画面内不烧录任何水印、台标、字幕或文字；画面外项目信息与发布文案中保留 AI 生成标识。

## 已知限制（README 自己承认的）

- 分镜规划是模板化：按开端 / 发展 / 转折 / 收尾的通用节拍生成分镜骨架，提示词需要人工细化。
- 终审的自动信号只有帧级启发式（亮度漂移、接缝差异、镜内场景跳变、曝光突变），其余 11 类信号没有 OCR 与唇读模型，只能靠人工复核。
- 对白逐字核对做不了，抽帧无法核口型；发布前请人工听一遍确认台词清楚。
- 响度统一是线性归一（loudnorm 单次），色温统一是全片同一档 eq，不是逐镜调色。
- 单机本地工具：SQLite + 本地文件，无多用户、无鉴权，不要直接暴露到公网。
- 6 条 / 轮上限是参照原插件的派发约束，不是视频模型本身的限制。

## 对我们的启发（对照 PixelAIGC 工作流）

1. **风格圣经**：人物/场景/视觉三段锁定，逐字放进每个镜头提示词前面——比我们现在“每段提示词里重复人物描述”更正式，可以直接抄这个结构。
2. **接力规则**：第 2 镜起从上一镜尾帧接续——解决镜头间跳变的好办法，值得在《柑橘味的夏天》第 2 集里试。
3. **批量抽卡 + 自动选片**：每镜抽 1–6 条候选再选最好的，比现在一段只生成一次、失败才重试更省人工。PixelAIGC 的“失败最多重试两次”可以升级成这个思路。
4. **终审 15 类假信号清单**：塑料皮肤、表情僵、光线色温漂移、服装发型跳变、身份漂移、接缝机位跳变、招牌乱码、道具消失、口型不清——可以直接拿来当我们的质检清单。
5. **规格与真实感分开计分**：时长/分辨率通过不等于片子能看，这个区分很好。
6. **二次剪辑方案**：接缝处硬切或 2–3 帧叠化、全片统一色温曝光、统一响度、轻颗粒破塑料感——可以写进我们的组装步骤。
7. **AI 标识**：画面内不烧录水印，画面外文案写“本片全部画面由 AI 生成，非实拍”——发平台时照这个做。
8. **不能直接用的地方**：它不自带视频模型，要接供应商 API 才能出真片子；我们的视频是 Muse 生成的，不是调 API，所以整套工具不能直接搬，只能学它的方法。
