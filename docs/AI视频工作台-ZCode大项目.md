# AI 视频生成工作台 — ZCode 大项目

> 给 ZCode 的完整开发任务书。目标：一个能真正用来做 AI 视频的完整工作台。
> 技术栈：React + TypeScript + Vite + Tailwind CSS + IndexedDB，全部前端本地运行，不需要后端。
>
> **项目文件夹**：`D:\pixelflow\` —— 所有代码都放在这个文件夹里，不要放到别处。ZCode 启动后先建这个文件夹再开始写代码。
>
> **开发要求**：按里程碑顺序做，每做完一个里程碑就 `npm run build` 验证通过再继续下一个。不要跳步骤，不要一次写完全部代码再调试。

---

## 一、项目概述

**项目名**：PixelFlow AI 视频工作台

**用途**：管理 AI 视频的完整生产流程，从写故事、分镜，到生成片段、质检、拼接成片。

**背景**：基于 PixelAIGC 的 16 步超长 AI 视频工作流（10 秒一片段、角色卡锁定、接力规则、QC 检查、ffmpeg 拼接）。现在全靠手动记表格和跑脚本，容易乱，需要一个工作台把全流程管起来。

**目标用户**：一个人做 AI 视频的创作者，每天生成几十到一百个片段，需要跟踪每个片段的状态、质检结果、重试次数、配额用量。

**核心痛点**：
- 片段多了记不住哪个过了哪个没过
- 角色脸崩了不知道是哪个分镜开始崩的
- 提示词改了就找不回旧版本
- 配额快用完了不知道
- 拼接的时候要手动算时间点和转场
- 发布的时候每个平台要的标题简介标签都不一样

## 二、技术要求

### 2.1 基础技术栈
- **框架**：React 18 + TypeScript + Vite
- **样式**：Tailwind CSS
- **状态管理**：Zustand（分多个 store：项目、片段、角色卡、提示词、QC）
- **本地数据库**：IndexedDB（用 idb 库封装），数据量大，localStorage 不够用
- **拖拽**：@dnd-kit/core（分镜排序、片段排序）
- **文件处理**：浏览器内读取视频片段信息（时长、分辨率、帧率），用 ffmpeg.wasm 做拼接预览（可选功能，做不完可以先留接口）
- **部署**：纯静态，`npm run build` 后能直接跑
- **代码质量**：TypeScript 严格模式（strict: true），所有组件有类型定义，不用 `any`，不用 `@ts-ignore`

## 三、核心系统（必须全部实现，每个系统都要有独立页面）

### 3.1 项目管理
- 创建 / 删除 / 复制项目（复制要连分镜、角色卡、提示词一起复制）
- 每个项目字段：名字、主题、一句话故事、目标时长（60秒 / 120秒 / 300秒 / 自定义）、画幅（16:9 横屏 / 9:16 竖屏 / 1:1）、风格（动漫 / 写实 / 赛璐璐 / 电影感 / 吉卜力风）
- 项目列表页：卡片式，每个卡片显示名字、主题、进度条（已完成片段 / 总片段）、QC 通过率、更新时间
- 项目详情页：顶部大进度条 + 四个数字（总分镜、已通过、待质检、失败）
- 项目导出 / 导入（JSON 文件，导出要包含项目 + 分镜 + 角色卡 + 提示词 + QC 记录）
- 删除项目要二次确认弹窗
- 项目搜索和筛选（按状态、按风格、按时间）

### 3.2 故事与分镜系统
- 一句话故事输入框 → 点"拆分镜"自动拆成 N 个 10 秒分镜（按故事长度估算，60 秒 = 6 个分镜）
- 每个分镜字段：编号、开始时间点（0s / 10s / 20s…）、一句话描述、画面内容（详细）、运镜（推近 / 拉远 / 环绕等）、台词 / 旁白、状态
- 分镜列表可拖拽调整顺序，改一个分镜的位置或删除一个，自动重算后面所有分镜的时间点
- 分镜状态：待写 / 待生成 / 生成中 / 待质检 / 通过 / 失败（6 种状态，不同颜色）
- 分镜卡片显示：编号、时间点、描述前两行、状态徽章、候选片段数量、QC 结果
- 点分镜卡片进详情：能看完整描述、提示词、候选片段、QC 报告
- 批量操作：选中多个分镜，批量改状态、批量生成提示词
- 分镜时间轴（横向）：一条时间线，每个 10 秒一段，颜色表示状态，点一段跳到对应分镜

### 3.3 角色卡系统（Style Bible）
- 每个角色一张卡，字段：名字、外貌（脸型、眼睛、头发、衣服）、性格、配音（用哪个 TTS、哪个声音）、备注
- 角色卡支持多时代：同一个角色可以有现代 / 古代 / 未来三个版本，每个版本独立一张卡，切换时代时提示词自动换卡
- 角色卡内容自动拼进每个分镜的提示词前面（原文照搬，一个字不改）
- 角色卡锁定规则说明写在页面上：卡只定脸、头发、衣服，不定动作和场景（动作和场景写在分镜里）
- 角色卡列表页：每个角色一张卡片，显示名字、头像占位、出现的分镜数
- 角色卡编辑：改了角色卡要弹窗提醒"会影响 N 个分镜的提示词，要不要重新生成提示词"
- 角色卡导出 / 导入（方便复用到别的项目）

### 3.4 提示词系统
- 每个分镜自动生成完整提示词，公式：`角色卡（原文） + 场景描述 + 风格词 + 运镜词 + 光线词 + 接力句`
- 接力规则：从第 2 个分镜开始，提示词自动在末尾加上"承接上一个分镜的尾帧，动作和位置连续"
- 提示词模板库：分三类（风格词、运镜词、光线词），每类可搜索、可收藏、点一下插入到提示词里
- 提示词编辑器：大文本框，显示字数，支持撤销 / 重做
- 提示词历史：每次保存生成新版本，版本号 v1 / v2 / v3…，能看任意两个版本的 diff，能回滚到旧版本
- 提示词复制按钮（一键复制到剪贴板）
- 提示词批量生成：选中多个分镜，一键按模板生成全部提示词

### 3.5 片段管理
- 每个分镜可上传 1–6 个候选片段（视频文件，记录文件名、时长、分辨率、文件大小）
- 候选片段对比：并排显示多个候选，每个显示缩略图占位、时长、评分，能点选"这个是最优"
- 片段自动打分：按时长（是不是 10 秒）、分辨率（达不达标）、文件大小给基础分，人工可以改分
- 片段信息字段：文件名、时长、分辨率、帧率、生成时间、用的哪个模型、提示词版本（v几）、状态、失败原因、重试次数
- 片段状态机：待生成 → 生成中 → 待质检 → 通过 / 失败 → 重试（最多 2 次，第 2 次还失败就标记"放弃"，要人工处理）
- 失败原因下拉选：黑帧 / 冻帧 / 动作错 / 穿帮（脸变 / 衣服变 / 道具变）/ 有 AI 文字 / 比例错 / 其他（可填文字）
- 片段列表筛选：按分镜、按状态、按模型、按失败原因

### 3.6 QC 质检系统
- 自动检查清单（15 项，每项都要有说明和例子）：
  1. 首帧和尾帧能看清吗（不能是黑的、糊的）
  2. 有黑帧吗（中间突然黑一下）
  3. 有冻帧吗（画面超过 1 秒完全不动）
  4. 动作逻辑对吗（比如开门的手方向对吗，拿杯子的手对吗）
  5. 人物脸变了吗（和角色卡对比）
  6. 衣服变了吗（颜色、款式和角色卡一致吗）
  7. 道具变了吗（伞的颜色、臂章、杯子）
  8. 有 AI 生成的文字吗（有就不过，文字要后期 overlay）
  9. 画面比例对吗（16:9 还是 9:16，别搞错）
  10. 亮度 / 色温和前后分镜一致吗（不能一个亮一个暗）
  11. 有闪烁吗（亮度忽明忽暗）
  12. 运镜顺滑吗（没有突然跳一下）
  13. 和上一个分镜接得上吗（位置、动作连续吗）
  14. 时长是 10 秒吗（误差 ±0.5 秒内算过）
  15. 分辨率达标吗（横屏 1280x720，竖屏 720x1280）
- QC 界面：左边是片段信息，右边是 15 项清单，每项三个按钮（通过 / 不通过 / 跳过），不通过要填原因
- 全部 15 项填完才能提交，提交后出 QC 报告
- QC 报告内容：片段名、分镜号、检查时间、15 项每项结果、总体通过 / 不通过、不通过的项列出来
- QC 报告可导出（Markdown / JSON）
- QC 统计：每个项目的通过率、哪个检查项最容易不过、最容易失败的分镜

### 3.7 配音系统
- 旁白 / 台词管理：每段台词字段（对应分镜、开始时间、结束时间、说话人、台词内容、配音状态）
- 配音方案选择：无配音（纯音乐）/ 真人配音 / 日语 TTS / 中文 TTS
- 配音规则提醒写在页面上：旁白只在成片剪好后才配，不要先配；音乐音量比旁白低 15dB
- TTS 供应商管理表：

  | StepAudio | 免费到 11-08 | 11-09 起约 2.85元/万汉字 | 2026-11-08 | 之前主力，11-09 开始收费 |

- 每个供应商可编辑额度和截止日期，快到期时在看板上提醒
- 配音文件上传（音频文件）和试听播放器
- 配音和分镜对齐检查：台词时长和分镜时长对得上吗，对不上标红提醒

### 3.8 拼接与导出
- 一键生成 ffmpeg 拼接脚本，脚本内容包括：
  - 按分镜顺序列出所有通过的片段文件
  - 转场：默认硬切，可选 2–3 帧溶解（在两个片段之间加 xfade）
  - 先统一分辨率到 1280x720（横屏）或 720x1280（竖屏）
  - 色彩统一参数：亮度、对比度、饱和度（给参考值，可调）
  - 加轻微胶片颗粒（noise 参数）
  - 音频：旁白音轨 + 音乐音轨，音乐音量比旁白低 15dB
  - 输出：mp4，H.264，faststart（方便手机播放）
- 拼接脚本预览（代码框，可复制），也支持下载 .sh / .bat 文件
- 成片信息预估：总时长（分镜数 × 10 秒）、分辨率、预估文件大小（按码率算）
- 发布套件生成：输入成片标题，自动生成四个平台的发布文案：
  - 抖音：标题（20 字内）+ 简介 + 5 个标签
  - B站：标题 + 简介 + 分区 + 标签
  - 视频号：标题 + 简介
  - YouTube：英文标题 + 简介 + 标签
- 发布文案里自动加 AI 声明（"本视频由 AI 生成"），不加水印

### 3.9 素材库
- 角色卡库：所有项目的角色卡汇总，点一下复制到当前项目
- 提示词模板库：风格词、运镜词、光线词三类，每类可搜索、可按标签筛选、可收藏
- 音乐库：音乐名、文件、时长、用在哪个项目、授权信息
- 历史项目复用：打开旧项目，勾选要复用的角色卡 / 风格词 / 音乐，一键复制到新项目
- 素材搜索框：全库搜索，支持按名字和标签搜

### 3.10 数据看板
- 顶部四个数字卡片：总项目数、总片段数、总成片时长、平均 QC 通过率
- 每日生成量柱状图（过去 30 天，每天生成了多少片段）
- 配额提醒：每天 100 片段上限，今天已用多少，还剩多少，用到 80% 变黄，100% 变红
- 成本统计表：每个模型用了多少次、每次大概多少 token / 多少钱
- 项目进度表：每个项目一行，显示进度条、通过率、失败数、更新时间
- QC 失败原因统计：饼图，哪个原因最多（脸崩 / 黑帧 / 穿帮…）

### 3.11 设置页面
- 默认画幅、默认风格、默认转场方式
- 每日配额上限（默认 100，可改）
- QC 严格程度（严格 / 标准 / 宽松，影响哪些项必须过）
- 主题：暗色 / 亮色
- 数据管理：导出全部数据（JSON）、导入、清空（要二次确认）

## 五、界面要求

### 5.1 整体布局
- **左侧导航栏**（固定，220px 宽）：项目、故事分镜、角色卡、提示词、片段、QC、配音、拼接、素材库、看板、设置、帮助
- **顶部栏**：当前项目名、进度、今日配额（已用 / 总数）、搜索框
- **主内容区**：白色 / 暗色卡片，圆角，阴影
- **暗色主题**：默认暗色（做视频的人晚上用得多），可切换亮色
- **字体**：中文用系统默认，英文 / 数字用等宽字体显示时间点

### 5.2 关键页面
- **项目列表页**：卡片网格，每个卡片有封面色块、名字、主题、进度条、通过率、更新时间
- **项目详情页**：顶部大进度条 + 四个数字；下面是分镜时间轴（横向，每个 10 秒一段，颜色表示状态）；再下面是分镜卡片列表
- **分镜卡片**：编号大字、时间点、描述前两行、状态徽章（6 色）、候选片段数、QC 结果（通过打勾 / 不通过打叉）
- **角色卡页面**：左侧角色列表，右侧选中角色的详情卡，可编辑
- **QC 页面**：左边片段信息（文件名、时长、分辨率），右边 15 项清单，每项三个按钮
- **看板页面**：四个数字卡片在上，图表在中，表格在下

### 5.3 交互细节
- 所有删除操作都要二次确认弹窗
- 所有耗时操作（生成、导出）要有 loading 状态
- 所有复制操作点完显示"已复制"提示 2 秒
- 表单必填项标红星，提交时验证
- 手机端：导航栏变底部 tab，卡片变单列，按钮要大（至少 44px 高）

## 六、开发里程碑（按顺序做，每做完一个就 build 验证）

### 第一阶段：骨架
1. **M1 项目骨架**：Vite + React + TS + Tailwind 跑起来，路由（12 个页面）、IndexedDB（9 张表）、暗色主题、左侧导航 + 顶部栏
2. **M2 项目管理**：创建 / 删除 / 复制项目，项目列表 + 进度显示，搜索筛选，导出导入 JSON

### 第二阶段：核心创作流
3. **M3 故事分镜**：一句话拆分镜，分镜增删改、拖拽排序、时间点自动重算、状态 6 色、时间轴

5. **M5 提示词系统**：自动生成公式、接力规则、模板库三类、编辑器（撤销重做）、历史版本 + diff + 回滚、复制按钮、批量生成

### 第三阶段：生产管理

### 第四阶段：输出

10. **M10 素材库**：角色卡库、提示词模板库、音乐库、历史项目复用、搜索
11. **M11 数据看板**：四个数字卡片、每日生成量柱状图、配额提醒（80% 黄 / 100% 红）、成本统计、项目进度表、QC 失败原因饼图

### 第五阶段：内容填充
